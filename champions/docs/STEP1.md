# ステップ1の解説: 個体の作成と能力値の計算

## 1. このステップで出来たこと

- プロジェクトの土台(React + Vite + TypeScript、テスト、型チェック)
- サンプルのポケモン10体のデータ(種族値、タイプ、特性、覚える技、メガシンカ)
- 能力値の計算と、能力ポイントの上限の決まり
- バトルギミックの共通の形と、その実装の1つとしてのメガシンカ
- 個体編集画面(入力するたびに実数値と残りポイントが変わる)。**保存はまだ出来ません**(ステップ2)
- ポケモンごとに違う「覚える技・持てる特性・対応するメガストーン」だけを選べる仕組み

サンプルの10体: ガブリアス、リザードン、サーナイト、メタグロス、カイリュー、バンギラス、ガオガエン、ウォッシュロトム、マリルリ、ピカチュウ

## 3. テスト例(入力と期待する結果)

どれも `src/calc/stats.test.ts` と `src/calc/battler.test.ts` に入っています。

ガブリアスの種族値は 108 / 130 / 95 / 80 / 85 / 102、メガガブリアスは 108 / 170 / 115 / 120 / 95 / 92 です。

| 例 | 入力 | 期待する実数値 |
|---|---|---|
| 1 | ガブリアス、ようき(すばやさ↑ とくこう↓)、HP 2・こうげき 32・すばやさ 32 | 185 / 182 / 115 / 90 / 105 / 169 |
| 2 | ガブリアス、ゆうかん(こうげき↑ すばやさ↓)、ポイントなし | 183 / 165 / 115 / 100 / 105 / 109 |
| 3 | 例1にガブリアスナイトを持たせてメガシンカ | 185 / 222 / 135 / 126 / 115 / 158 |
| 4 | 例1にガブリアスナイトZを持たせてメガシンカ | すばやさ 223(タイプはドラゴンのみ、特性は ふゆう) |

切り捨てが効く場所の計算:

- 例1 すばやさ: (102 + 20 + 32) × 1.1 = 169.4 → **169**
- 例2 すばやさ: (102 + 20) × 0.9 = 109.8 → **109**
- 例3 すばやさ: (92 + 20 + 32) × 1.1 = 158.4 → **158**
- 例4 すばやさ: (151 + 20 + 32) × 1.1 = 223.3 → **223**

上限の例:

| 入力 | 結果 |
|---|---|
| 1つの能力に 33 を入れる | 32 になる |
| こうげき 32・すばやさ 32(残り 2)のとき、HP に 10 を入れる | 2 になる(合計 66) |
| 合計がちょうど 66 のとき、ほかの能力を 1 増やす | 増えない |

## 4. 仕組み

### 4.1 入力してから表示が変わるまで

```
(1) 利用者が「こうげき」の + を押す
      |
(2) 画面(StatPointsEditor.tsx)が「31 にしたい」と伝える
      |
(3) setStatPoint (calc/statPoints.ts) が上限を確かめ、新しい能力ポイントの表を返す
      |
(4) 画面(IndividualEditor.tsx)が、編集中の個体を新しいものに置き換える   … setIndividual
      |
(5) React が画面を描き直す。そのとき、実数値などを個体から計算し直す
      buildBattler (calc/battler.ts) → calcStats (calc/stats.ts)
      |
(6) 新しい実数値と残りポイントが表示される
```

画面が覚えているのは「編集中の個体」1つだけです。実数値、残りポイント、選べる候補、入力チェックの結果は、
どれも覚えておかずに、個体から毎回計算します。こうすると「個体は変わったのに表示が古いまま」という
食い違いが起きません。

### 4.2 ファイルの役割(読む順番のおすすめ)

| 順番 | ファイル | 役割 |
|---|---|---|
| 1 | `src/domain/stats.ts` | 能力の名前(hp, atk, …)と、能力の表の形 |
| 2 | `src/calc/stats.ts` | 能力値の式。いちばん短く、このアプリの中心 |
| 3 | `src/calc/stats.test.ts` | 上の式のテスト。「入力 → 期待する結果」の書き方が分かる |
| 4 | `src/calc/statPoints.ts` | 能力ポイントの上限 |
| 5 | `src/domain/individual.ts` | 個体の形 |
| 6 | `src/data/index.ts` | マスターデータの形と読み込み |
| 7 | `src/gimmicks/types.ts` → `mega.ts` → `registry.ts` | ギミックの共通の形、メガシンカ、登録簿 |
| 8 | `src/calc/battler.ts` | 個体 → 戦闘中の姿(ギミックを適用して能力値を計算) |
| 9 | `src/domain/editIndividual.ts` | 選べる候補と、項目を変えるときの決まり |
| 10 | `src/features/individuals/IndividualEditor.tsx` | 画面。上の関数を呼んで表示するだけ |

`src/calc/` と `src/domain/` と `src/gimmicks/` には、画面の部品(React)が1つも出てきません。
計算と決まりを画面から分けてあるので、画面なしでテストできます。

### 4.3 出てくる考え方

**型(TypeScript)** — データの形をコードに書いたものです。

```ts
export interface Individual {
  speciesId: string;        // 文字
  itemId: string | null;    // 文字、または「なし」
  statPoints: StatTable;    // 6つの能力それぞれに数値
}
```

形に合わない使い方(例: `itemId` に数値を入れる、`statPoints.atk` を `statPoints.attack` と書き間違える)をすると、
実行する前にエディタと `npm run typecheck` が教えてくれます。

**純粋関数** — 同じ入力なら必ず同じ結果を返し、外のもの(画面、保存、引数で受け取った値)を変えない関数です。

```ts
export function calcHp(baseStat: number, statPoints: number): number {
  return baseStat + 75 + statPoints;
}
```

テストは「この入力なら、この結果」と書くだけで済みます。

**書き換えずに、新しく作る** — 個体を変えるときは、元の個体を書き換えず、変更後の新しい個体を作って返します。

```ts
return { ...individual, natureId };   // individual の中身を写し、natureId だけ差し替えた新しい個体
```

`...individual` は「中身をすべて写す」という書き方です。
React は「前と別の入れ物になったか」を見て画面を描き直すので、この書き方が必要です。

**useState(React)** — 画面が覚えておく値を作ります。

```tsx
const [individual, setIndividual] = useState(() => createFirstIndividual(data));
```

`individual` がいまの値、`setIndividual(新しい値)` で値を変えると、React が画面を描き直します。

**小数の誤差を避ける** — 性格補正は `× 1.1` と書かず、`× 11 ÷ 10` と整数で計算しています。
コンピュータは 1.1 を正確に表せず、わずかな誤差を持つためです。
このアプリで扱う範囲(1〜400)では、どちらの書き方でも結果が同じになることを確かめてありますが、
切り捨てを伴う計算は整数で書くのが安全で、ステップ4のダメージ計算でも同じ方針を使います。

## 5. ポケモンごとに違うものを、どう正しく入力できるようにしたか

| 違うもの | データのどこにあるか | 画面での扱い |
|---|---|---|
| 持てる特性 | `pokemon.json` の `abilities` | 特性の候補はこれだけ |
| 覚える技 | `pokemon.json` の `learnset` | 技の候補はこれだけ。ほかの欄で選んだ技は候補から消える |
| メガシンカ後の姿と必要なメガストーン | `pokemon.json` の `megaForms` | 持ち物の候補に出るメガストーンは自分用だけ。メガシンカと持ち物は必ず一致する |

守り方は2段構えです(`src/domain/` にあります)。

1. **入力を守る**(`editIndividual.ts`) — 候補を絞り、項目を変えたら合わなくなる項目も一緒に直す。
   たとえばポケモンを変えると、技は空欄に戻り、前のポケモン用のメガストーンは外れます
2. **データを調べる**(`validateIndividual.ts`) — 個体が決まりに合っているかを調べる。
   画面を通らないデータ(あとのステップで作る JSON の読み込みなど)のためのものです。
   いまは画面の「入力チェック」に結果を出しています

データそのものの間違いは `src/data/masterData.test.ts` が調べます
(種族値の6項目がそろっているか、覚える技がすべて技のデータにあるか、メガストーンが持ち物のデータにあるか、など)。

## 6. データの出典と、確認してほしいこと

| 出典 | 使っているもの |
|---|---|
| Pokémon Showdown(MIT) | 種族値、タイプ、特性、覚える技、技の性能、持ち物。チャンピオンズ用の変更を含む |
| PokéAPI(BSD 3条項) | 日本語名 |

- 数値や名前は `npm run data:build` が公開データから取り出したもので、手で書いたものはありません。
  10体分で、日本語名が見つからなかったものは 0 件でした
- 種族値は2つの出典で同じ値になることを確かめました(ガブリアス)
- **Pokémon Showdown は有志が管理する非公式のデータです。** ゲームの画面と見比べる確認は、この環境からは出来ていません。
  お手元のゲームで、よく使うポケモンの「覚える技」「特性」を数体ぶん見比べてもらえると確実です。
  違いがあったら教えてください

取得元のプログラムを読んで分かった、チャンピオンズ固有の決まり(同じにしてあります):

- 覚える技は、進化前のポケモンの技を引き継がない
- ウォッシュロトムは「ロトムの技 + ハイドロポンプ」を覚える
- とつげきチョッキなど、本編にあってもチャンピオンズでは使えない持ち物は、候補に出ない

## 7. 設計書から変わった点

| 変わった点 | 理由 |
|---|---|
| ID をハイフンなしにした(`dragon-claw` → `dragonclaw`) | データの取得元と同じ決まりにして、変換の間違いを無くすため |
| データの主な取得元を Pokémon Showdown にした | チャンピオンズ用の「覚える技」「使える持ち物」が入っているため |
| ギミックの共通の形に `syncSettings` と `shortLabel` を足した | メガシンカと持ち物を一致させるため/表の見出しを短くするため |
| 「技を変える」「ダメージ補正を加える」のフックは、まだ入れていない | 必要な形(技、補正)が決まるステップ4で足す |
| `domain/editIndividual.ts` と `validateIndividual.ts` を足した | ポケモンごとに違う選択肢を正しく扱うため |

設計書(`DESIGN.md`)にも反映してあります。
