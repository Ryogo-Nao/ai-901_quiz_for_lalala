# ステップ5の解説: JSON の書き出しと読み込み

## 1. 出来たこと

- 「設定」の画面
- 全データ(個体とチーム)を、1つの JSON ファイルに書き出す
- 書き出したファイルを読み込む。「いまのデータに追加する」か「置き換える」かを選べる
- 読み込む前に、ファイルに何件入っているかを表示する
- 上限(個体500体、チーム10個)を超えるとき、壊れたファイルのときは、読み込まずに理由を表示する。いまのデータは変わらない
- 古い形式のファイルは、マイグレーションで新しい形式に変換して読み込む
- レギュレーションの切り替え(選んだものは保存される)
- データの出典の表示

## 2. 動作確認の方法

個体を2体と、その2体を入れたチームを1つ作ってから試してください。

| # | 操作 | 期待する表示 |
|---|---|---|
| 1 | 「設定」→「ファイルに書き出す」 | `champions-tool-(日付).json` が保存される。下に内容も表示される |
| 2 | 「個体」で、個体をすべて削除する | 0 / 500。チームのメンバーも空になる |
| 3 | 「設定」→ 1 のファイルを選ぶ(または内容を貼り付ける) | 「個体 2体、チーム 1個が入っています」 |
| 4 | 「置き換える」を選んで押す | 「読み込みました。いまのデータ: 個体 2体、チーム 1個」 |
| 5 | 「個体」「チーム」を見る | 個体も、チームのメンバーも元に戻っている |
| 6 | 「設定」の貼り付け欄に、でたらめな文字を入れる | 「ファイルを読み取れませんでした」。データは変わらない |

iPhone の Safari では、書き出したファイルは「ファイル」アプリのダウンロードに入ります。
ファイルが保存されない環境では、表示された内容を「コピーする」で写して、メモなどに保管してください。

## 3. 書き出しファイルの形

```json
{
  "app": "champions-tool",
  "schemaVersion": 1,
  "exportedAt": "2026-11-16T12:00:00.000Z",
  "individuals": [ { "id": "…", "speciesId": "garchomp", "…": "…" } ],
  "teams": [ { "id": "…", "name": "メガ軸", "memberIds": ["…"], "…": "…" } ]
}
```

| 項目 | 役割 |
|---|---|
| `app` | このアプリのファイルだという目印。ほかのファイルを間違えて読み込まないため |
| `schemaVersion` | 保存形式のバージョン番号。古いファイルを変換するために使う |

## 4. 仕組み

`src/storage/exportImport.ts` は、前半が純粋関数、後半が IndexedDB の読み書きです。

| 関数 | 役割 | 純粋関数か |
|---|---|---|
| `buildExport` | 書き出しファイルの中身を作る | はい |
| `parseImport` | ファイルの文字を調べて、いまの形式の個体とチームにする | はい |
| `planImport` | いまのデータとどう合わせるかを決める(上限のチェックもここ) | はい |
| `exportAll` / `importAll` | 保存データを読む/書き換える | いいえ |

読み込みの流れ:

```
ファイルの文字
  | parseImport   JSON として読む → このアプリのファイルか確かめる
  |               → マイグレーション(古い形式なら変換)→ 足りない項目を補う
  v
読み込むデータ
  | planImport    「追加」か「置き換え」かで合わせる → 上限を確かめる
  |               → チームのメンバーを「実際にある個体」だけにする
  v
読み込んだあとのデータ
  | importAll     個体とチームを、1つのトランザクションで入れ替える
  v
保存データ
```

「調べる」「決める」を先にすべて済ませてから、最後に1回だけ書き換えます。
途中で問題が見つかったら、書き換える前に止まるので、いまのデータは壊れません。

**「追加する」のときの決まり**: 同じ id の個体・チームは、ファイルの内容で上書きします
(同じファイルを2回読み込んでも、2体に増えません)。

**マイグレーションとのつながり**: `parseImport` は、ステップ2で作った `migrate` を通します。
将来、保存形式を変えて `schemaVersion` を 2 に上げても、`migrations.ts` に変換を1つ足すだけで、
古いファイル(`schemaVersion: 1`)をそのまま読み込めます。
アプリより新しい形式のファイルは読み込まず、「アプリを更新してください」と知らせます。

## 5. レギュレーション

`src/data/regulations.json` に書いたものが、選択肢に出ます。

```json
[
  { "id": "sample-mega", "name": "(サンプル) メガシンカあり", "gimmicks": ["mega"] }
]
```

個体の編集とダメージ計算には、選んだレギュレーションの `gimmicks` に入っているギミックだけが出ます。
実際のレギュレーションを足すときは、ゲーム内の表示を見て、このファイルに1つ書き足してください。
