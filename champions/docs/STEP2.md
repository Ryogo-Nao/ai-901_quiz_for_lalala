# ステップ2の解説: 個体の保存

## 1. このステップで出来たこと

- 個体をブラウザの中(IndexedDB)に保存する。ページを閉じても残る
- 個体の一覧(件数の表示、名前で探す、編集、複製、削除)
- 上限500体。達したら「新しく作る」「複製」が押せなくなり、理由を表示する
- 編集画面の「保存」ボタンと、未保存のまま戻ろうとしたときの確認
- 保存形式のバージョン番号(`schemaVersion`)と、マイグレーションの土台
- 技の選択欄を変更: 選ぶときは技の名前だけ。選んだ技のタイプ・分類・威力は欄の下に表示

## 2. 動作確認の方法

### 2.1 自動テスト

```bash
npm install    # ライブラリが増えたので、もう一度実行する
npm test       # 「143 passed」と出れば合格
```

## 3. 仕組み

### 3.1 役割の分け方

```
IndividualsPage.tsx      保存データを読む・書く。一覧と編集のどちらを出すか決める
  ├ IndividualList.tsx     一覧を表示するだけ
  └ IndividualEditor.tsx   1体を編集するだけ
        |
        | 「保存して」「削除して」と頼む
        v
storage/individuals.ts   個体の読み書き(上限のチェックもここ)
        |
        v
storage/db.ts            IndexedDB を開く。保存場所(ストア)を作る
storage/migrations.ts    保存形式のバージョン番号と、古い形式からの変換
```

一覧と編集画面は、保存のしかたを知りません。画面と保存を分けてあるので、
保存の部分だけを `storage/individuals.test.ts` でテストできます。

### 3.2 編集中の変更は、保存するまで保存データに影響しない

編集画面は、開いたときの個体を「写し」として持ち、その写しだけを変えます。
「保存」を押したときに初めて `saveIndividual` が呼ばれ、IndexedDB が書き換わります。
この考え方は、ステップ4のダメージ計算(呼び出した個体を一時的に変える)でもそのまま使います。

### 3.3 上限のチェックは「数える」と「保存する」を1まとまりで行う

```ts
const tx = db.transaction('individuals', 'readwrite');   // ひとまとまりの読み書きを始める
const isNew = (await tx.store.getKey(saved.id)) === undefined;
if (isNew && (await tx.store.count()) >= MAX_INDIVIDUALS) { /* 中止してエラー */ }
await tx.store.put(saved);
await tx.done;                                           // ここまで成功して、初めて確定する
```

このまとまりを**トランザクション**と呼びます。別々に行うと、数えたあと保存するまでの間に
別のタブで追加されて、上限を超えるおそれがあります。すでにある個体の上書きは、上限に達していても出来ます。

### 3.4 バージョン番号が2種類ある

| 番号 | 何の番号か | いつ上げるか |
|---|---|---|
| `DB_VERSION`(db.ts) | 保存場所の構造 | ストアを増やすとき |
| `CURRENT_SCHEMA_VERSION`(migrations.ts) | 個体やチームの中身の形 | 項目の名前や構造や意味を変えるとき |

項目を**足すだけ**なら、どちらも上げません。読むときに `normalizeIndividual` が初期値を補います
(例: `gimmicks` が無い古い個体は「ギミックの設定なし」として読める)。

アプリより新しい形式のデータを見つけたときは、何も書き換えずに「アプリを更新してください」と知らせます。

### 3.5 新しく出てきた書き方

**async / await** — 保存や読み込みは、終わるまで少し時間がかかります。
`await` は「終わるまで待つ」、`async` は「この関数の中で await を使う」という印です。

```ts
export async function listIndividuals(): Promise<Individual[]> {
  const db = await getDb();                  // データベースが開くのを待つ
  const all = await db.getAll('individuals'); // 読み終わるのを待つ
  ...
}
```

**useEffect(React)** — 画面が表示されたあとに行う処理を書く場所です。ここで保存データを読み込んでいます。

**try / catch** — 失敗するかもしれない処理を `try` に書き、失敗したときの対応を `catch` に書きます。
保存に失敗したら、理由を画面に出します。

## 4. 知っておいてほしいこと

- 保存データは「その端末の、そのブラウザの、そのアドレス」ごとに別々です。
  PC で保存した個体は、スマホには出ません。別の端末へ移す機能(JSON の書き出し/読み込み)はステップ5で作ります
- ブラウザの「サイトのデータを消去」を行うと、保存データも消えます
- プライベートブラウズでは保存できない、または閉じると消えることがあります
