# 4-1 計算式の本体

## 1. 出来たこと

- ダメージ計算の本体。16通りのダメージ、最小〜最大、HPに対する割合、確定数を返す
- 丸めの決まり(切り捨て、五捨五超入、補正の連鎖、ランク補正)
- 「補正を順番に適用する流れ」。特性・持ち物・ギミックの補正を、あとから差し込める形
- ギミックの共通の形に、残り2つのフック(技を変える、ダメージ補正を加える)を追加
- 手本の計算機(@smogon/calc)との突き合わせテスト

**画面はまだありません**(4-3 で作ります)。この段階の確認は、自動テストで行います。

## 2. 動作確認の方法

```bash
npm install    # 突き合わせ用の手本を追加したので、もう一度実行する
npm test       # 「217 passed」と出れば合格
```

テストの中身は2種類です。

| 種類 | ファイル | 何を確かめているか |
|---|---|---|
| 手で計算した値と比べる | `src/calc/damage/pipeline.test.ts` など | 下の「テスト例」。計算の途中の値まで確かめる |
| 手本と大量に比べる | `src/calc/damage/crossCheck.test.ts` | サンプル10体(メガシンカ後を含む12通り)の総当たり × 覚える技すべて × 条件9通り。16通りのダメージが1つ残らず一致すること |

突き合わせは合計1万件以上あり、すべて一致しています。

## 3. テスト例(入力と期待する結果)

**例1: ガブリアスの じしん → メタグロス**

- 攻撃側: ガブリアス、ようき、HP 2・こうげき 32・すばやさ 32 → こうげき **182**
- 防御側: メタグロス、がんばりや、ポイントなし → HP **155**、ぼうぎょ **150**
- 技: じしん(じめん・物理・威力 100)。タイプ一致、相性は ばつぐん(はがねに2倍、エスパーに等倍)

| 段階 | 計算 | 値 |
|---|---|---|
| 基礎ダメージ | floor(floor(22 × 100 × 182 ÷ 150) ÷ 50) + 2 = floor(2669 ÷ 50) + 2 | **55** |
| 乱数 85(最小) | floor(55 × 85 ÷ 100) | 46 |
| タイプ一致 | 46 × 1.5 = 69.0 | 69 |
| タイプ相性 | 69 × 2 | **138** |
| 乱数 100(最大) | 55 | 55 |
| タイプ一致 | 55 × 1.5 = 82.5 → 五捨五超入で切り捨て | 82 |
| タイプ相性 | 82 × 2 | **164** |

- 16通り: 138, 140, 140, 144, 144, 146, 150, 150, 152, 152, 156, 156, 158, 158, 162, 164
- 割合: 138 ÷ 155 = **89.0%** 〜 164 ÷ 155 = **105.8%**
- 確定数: HP 155 以上になるのは 16通り中 6通り → **乱数1発(37.5%)**

**例1に条件を足したとき**

| 条件 | 途中の値 | ダメージ |
|---|---|---|
| 急所 | 基礎ダメージ 55 × 1.5 = 82.5 → 82 | 206 〜 246 |
| 範囲技 | 基礎ダメージ 55 × 0.75 = 41.25 → 41 | 最大 122 |
| やけど | 最後に半分 | 最大 82 |
| こうげきランク +2 | こうげき 182 → 364、基礎ダメージ 108 | - |
| 急所 + 防御側のぼうぎょランク +6 | ぼうぎょは 150 のまま(急所は相手の上がったランクを無視) | - |

## 4. 仕組み

### 4.1 計算の流れ

```
攻撃側 + 技 + 防御側 + 条件
  |
  | A. 技を確定        ギミックが技を変えることがある(いまは該当なし)
  | B. 補正を集める    ルール(タイプ一致・急所・やけど・範囲技)+ ギミック → Modifier の一覧
  | C. 段階の順番どおりに適用
  v
  1 威力 → 2 攻撃 → 3 防御 → 4 基礎ダメージ → 5 範囲 → 6 天気 → 7 急所
  → 8 乱数(16通り) → 9 タイプ一致 → 10 タイプ相性 → 11 やけど → 12 最終補正 → 13 最低1
  v
ダメージ16通り → 最小〜最大 / 割合 / 確定数
```

### 4.2 ファイルの役割(読む順番のおすすめ)

| 順番 | ファイル | 役割 |
|---|---|---|
| 1 | `src/calc/rounding.ts` | 五捨五超入、補正の連鎖、ランク補正 |
| 2 | `src/calc/damage/modifier.ts` | 補正(Modifier)の形と、段階の順番表 |
| 3 | `src/calc/damage/coreRules.ts` | 基本のルール4つ。「入力を見て Modifier を返す関数」 |
| 4 | `src/calc/damage/pipeline.ts` | 本体。採用した式を冒頭のコメントに書いてある |
| 5 | `src/calc/damage/ko.ts` | 確定数 |
| 6 | `src/calc/damage/unsupportedMoves.ts` | まだ正しく計算できない技の一覧 |

### 4.3 補正は、4096 を基準にした整数で持つ

ゲームは 1.5 倍を `6144`、0.75 倍を `3072` のように、4096 を 1.0 倍とした整数で持っています。
このアプリも同じ整数で計算します。五捨五超入も、小数を使わずに整数だけで行います。

```ts
export function applyMod(value: number, mod: number): number {
  return Math.floor((value * mod + 2047) / MOD_BASE);   // MOD_BASE = 4096
}
```

`value × mod` を 4096 で割ったあまりが 2048 より大きいときだけ切り上げたい。
2047 を足してから切り捨てると、ちょうどそうなります。

### 4.4 ルールを足しても、本体は変わらない

```ts
export const criticalRule: ModifierRule = ({ conditions }) =>
  conditions.isCritical ? [{ stage: 'critical', value: 6144, label: '急所' }] : [];
```

ルールは「どの段階で、どれだけ」を返すだけです。4-2 で足す持ち物や特性も、同じ形のルールになります。
各 Modifier には `label` があるので、画面で「適用された補正の内訳」を出せます。

### 4.5 確定数は、組み合わせをすべて数える

1発目の16通りそれぞれに2発目の16通りを足し…と、合計ダメージとその確率の表を1発ずつ進めます。
合計がHP以上になったものは「倒せた」としてまとめるので、表が大きくなりすぎません。
10発でも倒せないときは、そこで打ち切ります。

> 4-1 の時点では「まだ正しく計算できない技」がありましたが、4-2 で対応しました(下の 4-2 を参照)。

# 4-2 補正と、特別な決まりを持つ技

## 1. 出来たこと

- **場の状態**: 天気(はれ・あめ・すなあらし・ゆき)、フィールド(4種類)、壁(リフレクター・ひかりのかべ・オーロラベール)、てだすけ、シングル/ダブル
- **状態とHP**: 状態異常(やけど・まひ・どく など)、いまのHP
- **持ち物**: いのちのたま、たつじんのおび、タイプ強化の持ち物(もくたん など18種類)、ちからのハチマキ、ものしりメガネ、
  でんきだま、ノーマルジュエル、半減のきのみ(18種類)、ふうせん、くろいてっきゅう、こだわりスカーフ(すばやさ)、シード(4種類)
- **特性**: 攻撃側・防御側あわせて70種類以上(ちからもち、かたいツメ、マルチスケイル、ふゆう、あついしぼう、てきおうりょく、
  スキン系、メガソーラー、かたやぶり、てんねん など)
- **特別な決まりを持つ技**: 4-1 で「未対応」だった技を、ほぼすべて計算できるようにした

| 種類 | 技の例 | 決まり |
|---|---|---|
| 別の能力値を使う | イカサマ / ボディプレス / サイコショック | 相手の こうげき / 自分の ぼうぎょ / 相手の ぼうぎょ で計算 |
| 相手のランクを無視する | ＤＤラリアット | 相手の防御側のランクを 0 として計算 |
| 条件で威力が変わる | からげんき、はたきおとす、アクロバット、たたりめ、ウェザーボール | 状態異常、持ち物、天気などで決まる |
| 重さで決まる | けたぐり、くさむすび、ヘビーボンバー、ヒートスタンプ | 重さ(メガシンカ後は、その姿の重さ) |
| すばやさで決まる | ジャイロボール、エレキボール、しっぺがえし | ランク・こだわりスカーフ・まひ を反映した すばやさ |
| HPで決まる | きしかいせい、じたばた、ハードプレス | いまのHP |
| ランクで決まる | アシストパワー、つけあがる | 上がっているランクの合計 |
| 決まったダメージ | ナイトヘッド | レベルと同じ 50 |
| 連続技 | ロックブラスト、スケイルショット、トリプルアクセル | 1回ずつ計算して合計する |

## 2. 仕組み: 計算の前に「状況を整理する」

特性や持ち物は、お互いに打ち消し合うことがあります(かたやぶり が ふゆう を無視する、など)。
そこで、補正を集める前に、状況を1か所で整理します(`src/calc/damage/situation.ts`)。

```
入力(攻撃側・防御側・技・場)
  |
  | 状況を整理する (situation.ts)
  |   ・いま効いている特性と持ち物       (かたやぶり、ぶきよう、シードの消費)
  |   ・技のタイプ                       (ウェザーボール、スキン系の特性)
  |   ・どの能力値とランクを使うか       (イカサマ、ボディプレス、急所、てんねん)
  |   ・急所になるか、相性はいくつか
  |   ・当たるか                         (特性・持ち物・フィールドによる無効)
  |   ・補正を掛ける前の威力             (rules/movePower.ts)
  v
整理した状況 (Situation)
  |
  | 補正を集める (rules/power.ts, stats.ts, damage.ts)
  v
補正の一覧 → 段階の順番どおりに適用 (pipeline.ts)
```

ルールは「整理した状況を見て、補正を返す関数」です。たとえば いのちのたま は次の1行です。

```ts
else if (s.attackerItem === 'lifeorb') result.push(mod('final', 5324, itemName(s, 'lifeorb')));
```

| ファイル | 中身 |
|---|---|
| `rules/movePower.ts` | 威力が状況で決まる技の、威力の決め方 |
| `rules/power.ts` | 威力に掛かる補正(技の条件、てだすけ、フィールド、特性、持ち物) |
| `rules/stats.ts` | 攻撃と防御の能力値に掛かる補正 |
| `rules/damage.ts` | 範囲、天気、急所、タイプ一致、やけど、壁、最終補正 |

## 3. 手本との突き合わせ

`src/calc/damage/crossCheck.test.ts` が、次の組み合わせで、16通りのダメージを手本と比べます。

- ポケモン: データにある全ポケモン × 持てる特性すべて + メガシンカ後の姿(いまは29通り)
- 技: 覚える技すべて
- 条件: 37通り(急所、状態異常、ランク、天気4種類、フィールド4種類、壁、ダブル、HP、持ち物の組み合わせ15通り など)

`npm test` では時間を抑えるために一部の組み合わせだけを試します。すべてを試すときは次のようにします(3分ほどかかります)。

```bash
VITE_CROSS_CHECK=full npm test
```

**すべての組み合わせで、手本と一致することを確かめました。**

## 4. 計算に入っていないもの(正直なところ)

| 入っていないもの | 理由 | 画面での扱い |
|---|---|---|
| カウンター、ふくろだたき | 受けたダメージや、味方の能力で決まる | 「計算できません」と理由を表示 |
| がむしゃら | 相手のHPを自分と同じにする技 | 同上 |
| ダメおし、ゆきなだれ、じだんだ、りんしょう など | 「前の行動」で威力が2倍になる | 2倍にしない値を出し、注意を表示 |
| そうだいしょう、アナライズ、はりこみ、もらいびの強化 など | 画面で指定できない条件で決まる | 「この特性の補正は入っていません」と表示 |
| いかく | 自動では下げない | こうげきランクを -1 にして計算する |
| メトロノーム(持ち物) | 連続で使った回数で決まる | 補正なしで計算 |

## 5. チャンピオンズ専用の計算との違い

手本(@smogon/calc)は、チャンピオンズ用の計算を別に持っています。本編(第9世代)との違いは次の1点でした。

- **よびみず**: 本編では みず技を無効にします。手本のチャンピオンズ用の計算では、無効にしていません。
  このアプリは、ご指定どおり本編の決まり(無効にする)で作ってあります。
  いまのサンプル10体に よびみず を持つポケモンはいないので、結果に影響はありません。
  ゲームで確かめて違っていたら、`src/calc/damage/situation.ts` の `stormdrain` を1か所消すだけで直せます。

# 4-3 画面

## 1. 出来たこと

- 攻撃側・防御側: 保存した個体を呼び出すか、その場で作る。ポケモン・性格・特性・持ち物・能力ポイント・メガシンカも変えられる
- **呼び出した個体を変えても、保存データは変わらない**(写しを変えているため)
- 技: 個体に覚えさせた技を先に、そのほかの覚える技をあとに並べる

# 4-4 画面の作り直しと、全ポケモンへの対応

実際に使われているダメージ計算ツールの画面を参考に、次の2点を見直しました。

## 1. 何もしなくても、すべてのポケモンで計算できる

- データを、サンプルの10体から、**チャンピオンズで使えるポケモンすべて(263体、メガシンカ後の姿 82)** に広げた
  (`scripts/data-config.json` の `pokemon` を `"all"` にして `npm run data:build`)
- ダメージ計算の画面は、開いた直後から、ポケモンを選ぶだけで計算できる。個体を保存しておく必要は無い
- 自分で作った個体は、各欄の右上の「保存した個体から呼ぶ」で呼び出せる
- ポケモンが多いので、名前の一部(ひらがなでも可)を入力して候補を絞れるようにした
- 全ポケモンで、手本との突き合わせをやり直した。新しく対応したもの:
  てんきや(ポワルンのタイプが天気で変わる)、シェルアームズ(物理と特殊の有利なほうになる)、いのちがけ(自分のHPぶんのダメージ)
- 取得元に日本語名が無かったものが5件あり、英語名のまま入っている
  (特性 Aura Guard / Eelevate / Fire Mane、イキリンコの色違いの姿2つ)。
  ゲーム内の名前が分かれば、`scripts/name-overrides.json` に書くと日本語になる

## 2. 攻撃側には「上げる条件」、防御側には「減らす条件」

| 箱 | 入れるもの |
|---|---|
| 攻撃側 | ポケモン、技(タイプ・分類・威力)、攻撃に使う能力(実数値・能力ポイント・性格補正・ランク補正)、特性、持ち物、急所、てだすけ、状態異常 |
| 防御側 | ポケモン、HP と、受けるのに使う能力(実数値・能力ポイント・性格補正・ランク補正)、特性、持ち物、リフレクター、ひかりのかべ、オーロラベール、状態異常、いまのHP |
| その他 | 対戦形式(シングル/ダブル)、天気、フィールド、攻守の入れ替え |

- 能力の欄は、**いまの技で計算に使う能力だけ**を出す。物理技なら こうげき と ぼうぎょ、特殊技なら とくこう と とくぼう に切り替わる
- 性格補正は「0.9 / 1.0 / 1.1」で選ぶ。合う性格を自動で選び、名前を横に出す(`src/domain/nature.ts`)
- メガシンカ後の姿を選ぶと、持ち物がメガストーンになり、その姿で計算する

## 3. 確認の例(参考にした画面と同じ条件)

| 入力 | 期待する表示 |
|---|---|
| 攻撃側 ガブリアス、こうげきの能力P 32、性格補正 1.0、技 げきりん / 防御側 カバルドン(何も変えない) | こうげき 182、HP 183、ぼうぎょ 138、**90 〜 106、49.1% 〜 57.9%** |
| 上の状態で、攻撃側の性格補正を 1.1 に | こうげき 200、99 〜 117 |
| 性格補正を 1.0 に戻し、ランク補正を +1 に | 135 〜 159 |

# 4-5 登場時のダメージ(ステルスロック、まきびし)

防御側の「ダメージが減る・増える条件」に、ステルスロック(チェック)と、まきびし(0〜3回)を足しました。

| 場にあるもの | ダメージ |
|---|---|
| ステルスロック | 最大HP × いわタイプの相性 ÷ 8(等倍 1/8、ばつぐん 1/4、4倍 1/2、いまひとつ 1/16、4分の1 1/32) |
| まきびし | 1回 最大HP の 1/8、2回 1/6、3回 1/4。ひこうタイプ・ふゆう・ふうせん は受けない |

- 小数点以下は切り捨て、最低 1 ダメージ。特性「マジックガード」は受けない
- 画面には、登場時のダメージ(内訳と割合)と、受けたあとの残りHPを出す
- **技のダメージの確定数は、登場時のダメージを受けたあとのHPで計算する**(結果に「登場時ダメージ込み」と出る)。
  HP が満タンでなくなるので、マルチスケイル の半減も効かなくなる
- 登場時のダメージだけで倒れる場合は、そのことを表示する
- 計算は `src/calc/hazards.ts`、テストは `src/calc/hazards.test.ts`

確認の例(防御側 カバルドン、HP 183):

| 入力 | 期待する表示 |
|---|---|
| ステルスロック | 登場時のダメージ 11(6.0%)、残りHP 172 / 183 |
| ステルスロック + まきびし3回 | 登場時のダメージ 56(ステルスロック 11 + まきびし 45)、残りHP 127 / 183 |
| 防御側を リザードン(HP 153)に | ステルスロック 76、まきびし 0(浮いているので受けない) |
