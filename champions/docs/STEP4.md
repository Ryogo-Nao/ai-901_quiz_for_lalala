# 4-1 計算式の本体

## 1. 出来たこと

- ダメージ計算の本体。16通りのダメージ、最小〜最大、HPに対する割合、確定数を返す
- 丸めの決まり(切り捨て、五捨五超入、補正の連鎖、ランク補正)
- 「補正を順番に適用する流れ」。特性・持ち物・ギミックの補正を、あとから差し込める形
- ギミックの共通の形に、残り2つのフック(技を変える、ダメージ補正を加える)を追加
- 手本の計算機(@smogon/calc)との突き合わせテスト

**画面はまだありません**(4-3 で作ります)。この段階の確認は、自動テストで行います。

## 2. 動作確認の方法

```bash
npm install    # 突き合わせ用の手本を追加したので、もう一度実行する
npm test       # 「217 passed」と出れば合格
```

テストの中身は2種類です。

| 種類 | ファイル | 何を確かめているか |
|---|---|---|
| 手で計算した値と比べる | `src/calc/damage/pipeline.test.ts` など | 下の「テスト例」。計算の途中の値まで確かめる |
| 手本と大量に比べる | `src/calc/damage/crossCheck.test.ts` | サンプル10体(メガシンカ後を含む12通り)の総当たり × 覚える技すべて × 条件9通り。16通りのダメージが1つ残らず一致すること |

突き合わせは合計1万件以上あり、すべて一致しています。

## 3. テスト例(入力と期待する結果)

**例1: ガブリアスの じしん → メタグロス**

- 攻撃側: ガブリアス、ようき、HP 2・こうげき 32・すばやさ 32 → こうげき **182**
- 防御側: メタグロス、がんばりや、ポイントなし → HP **155**、ぼうぎょ **150**
- 技: じしん(じめん・物理・威力 100)。タイプ一致、相性は ばつぐん(はがねに2倍、エスパーに等倍)

| 段階 | 計算 | 値 |
|---|---|---|
| 基礎ダメージ | floor(floor(22 × 100 × 182 ÷ 150) ÷ 50) + 2 = floor(2669 ÷ 50) + 2 | **55** |
| 乱数 85(最小) | floor(55 × 85 ÷ 100) | 46 |
| タイプ一致 | 46 × 1.5 = 69.0 | 69 |
| タイプ相性 | 69 × 2 | **138** |
| 乱数 100(最大) | 55 | 55 |
| タイプ一致 | 55 × 1.5 = 82.5 → 五捨五超入で切り捨て | 82 |
| タイプ相性 | 82 × 2 | **164** |

- 16通り: 138, 140, 140, 144, 144, 146, 150, 150, 152, 152, 156, 156, 158, 158, 162, 164
- 割合: 138 ÷ 155 = **89.0%** 〜 164 ÷ 155 = **105.8%**
- 確定数: HP 155 以上になるのは 16通り中 6通り → **乱数1発(37.5%)**

**例1に条件を足したとき**

| 条件 | 途中の値 | ダメージ |
|---|---|---|
| 急所 | 基礎ダメージ 55 × 1.5 = 82.5 → 82 | 206 〜 246 |
| 範囲技 | 基礎ダメージ 55 × 0.75 = 41.25 → 41 | 最大 122 |
| やけど | 最後に半分 | 最大 82 |
| こうげきランク +2 | こうげき 182 → 364、基礎ダメージ 108 | - |
| 急所 + 防御側のぼうぎょランク +6 | ぼうぎょは 150 のまま(急所は相手の上がったランクを無視) | - |

## 4. 仕組み

### 4.1 計算の流れ

```
攻撃側 + 技 + 防御側 + 条件
  |
  | A. 技を確定        ギミックが技を変えることがある(いまは該当なし)
  | B. 補正を集める    ルール(タイプ一致・急所・やけど・範囲技)+ ギミック → Modifier の一覧
  | C. 段階の順番どおりに適用
  v
  1 威力 → 2 攻撃 → 3 防御 → 4 基礎ダメージ → 5 範囲 → 6 天気 → 7 急所
  → 8 乱数(16通り) → 9 タイプ一致 → 10 タイプ相性 → 11 やけど → 12 最終補正 → 13 最低1
  v
ダメージ16通り → 最小〜最大 / 割合 / 確定数
```

### 4.2 ファイルの役割(読む順番のおすすめ)

| 順番 | ファイル | 役割 |
|---|---|---|
| 1 | `src/calc/rounding.ts` | 五捨五超入、補正の連鎖、ランク補正 |
| 2 | `src/calc/damage/modifier.ts` | 補正(Modifier)の形と、段階の順番表 |
| 3 | `src/calc/damage/coreRules.ts` | 基本のルール4つ。「入力を見て Modifier を返す関数」 |
| 4 | `src/calc/damage/pipeline.ts` | 本体。採用した式を冒頭のコメントに書いてある |
| 5 | `src/calc/damage/ko.ts` | 確定数 |
| 6 | `src/calc/damage/unsupportedMoves.ts` | まだ正しく計算できない技の一覧 |

### 4.3 補正は、4096 を基準にした整数で持つ

ゲームは 1.5 倍を `6144`、0.75 倍を `3072` のように、4096 を 1.0 倍とした整数で持っています。
このアプリも同じ整数で計算します。五捨五超入も、小数を使わずに整数だけで行います。

```ts
export function applyMod(value: number, mod: number): number {
  return Math.floor((value * mod + 2047) / MOD_BASE);   // MOD_BASE = 4096
}
```

`value × mod` を 4096 で割ったあまりが 2048 より大きいときだけ切り上げたい。
2047 を足してから切り捨てると、ちょうどそうなります。

### 4.4 ルールを足しても、本体は変わらない

```ts
export const criticalRule: ModifierRule = ({ conditions }) =>
  conditions.isCritical ? [{ stage: 'critical', value: 6144, label: '急所' }] : [];
```

ルールは「どの段階で、どれだけ」を返すだけです。4-2 で足す持ち物や特性も、同じ形のルールになります。
各 Modifier には `label` があるので、画面で「適用された補正の内訳」を出せます。

### 4.5 確定数は、組み合わせをすべて数える

1発目の16通りそれぞれに2発目の16通りを足し…と、合計ダメージとその確率の表を1発ずつ進めます。
合計がHP以上になったものは「倒せた」としてまとめるので、表が大きくなりすぎません。
10発でも倒せないときは、そこで打ち切ります。

## 5. 分かったこと・決めたこと

**まだ正しく計算できない技がある。** 手本と突き合わせた結果、ふつうの式に当てはまらない技が見つかりました。
これらは、間違った数字を出さないよう、計算せずに「未対応」と返します。4-2 で対応していきます。

| 種類 | サンプルのポケモンが覚える技の例 |
|---|---|
| ふつうと違う能力値を使う | サイコショック、ボディプレス、イカサマ |
| 相手のランクを無視する | ＤＤラリアット |
| 状況で威力が変わる・失敗する | からげんき、はたきおとす、メテオビーム、アイアンローラー、ポルターガイスト |
| 威力が状況で決まる(22個) | アクロバット、けたぐり、ヘビーボンバー、アシストパワー など |
| 決まったダメージを与える | カウンター、ナイトヘッド、がむしゃら |

**連続技は、1回ぶんのダメージを計算する**(ロックブラスト、スケイルショット)。回数ぶんの合計は 4-3 の画面で扱います。

**ポケモンを足したとき**は、`npm test` を実行すると、足したポケモンの技も自動で手本と突き合わされます。
新しい「特別な決まりを持つ技」が混ざっていれば、テストが失敗して技の名前が分かります。

**チャンピオンズ専用の計算との違い。** 手本の `@smogon/calc` は、チャンピオンズ用の計算を別に持っています。
4-1 の範囲(基本の式)では、ご指定の第9世代の式と結果がすべて一致しました。
4-2 で特性や持ち物を足すときに違いが見つかったら、勝手に変えずに報告します。
